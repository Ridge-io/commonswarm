# CommonSwarm v0.1.8

Sign-out now tells you what the server actually did, and gives you a way out when it cannot.

## `cswarm logout` could leave you with no way back in

If your session had expired, `cswarm status` told you to log in — and `cswarm logout`, the
obvious way to reset, **failed and left the credential in place**. There was no way out of
that state from the CLI. That is fixed: a credential the server positively identifies as dead is
now cleared, and the command says what happened. A failure it cannot classify keeps the
credential and points you at `cswarm logout --local`, which clears this device without
contacting the server.

## It no longer claims a sign-out the server refused

The client library deliberately hides 401/403/404 responses to a sign-out request so that
browser apps can still clear local state. The CLI was inheriting that silence and printing
*"Signed out on all devices"* about requests the server had **refused**.

Now the CLI reads the server's actual answer:

- **The server confirmed it** → it says so, and only then.
- **The sign-out was not confirmed** → your credential is kept, because it is the only handle
  you have for retrying. The command does not guess at *why*: the client library reports a
  server that answered 500 the same way it reports one that never answered, so any cause named
  would be a guess. The remedy is the same either way — retry, or `--local`.

If you use `--all-devices` for containment, this is the difference between believing the
request went through and knowing it. Note the limit stated below: a confirmed sign-out revokes
refresh tokens, and access tokens already issued stay valid until they expire.

## Retrying a failed sign-out now works

Every failure path told you to run `cswarm logout` again. But the attempt had already consumed
your stored token and nothing wrote the replacement back, so the retry ran on a spent
credential. It now persists the rotated token before attempting the sign-out.

## `cswarm logout --local`

Clears this device without contacting the server. For when you cannot reach it, or do not want
to wait. Any session the server still holds stays live until it is revoked — the command says
so when you use it.

## Upgrading

```
curl -fsSL https://commonswarm.com/install.sh | sh
```

Requires Node >= 24. No configuration changes. Existing logins, workspaces, and agent
credentials are unaffected.

## Known limits

- **A confirmed sign-out does not invalidate already-issued access tokens** before they expire.
  This is how the underlying auth service works and is unchanged by this release.
- **Sign-out is not classified beyond confirmed-or-not.** A sign-out that was not confirmed is
  reported as such and your
  credential is kept, whatever the reason. Deciding that a particular refusal means "already
  gone, safe to delete" is exactly the guess that produced three earlier defects on this path,
  so the command does not make it.
- **Remote device listing, renaming, and revocation remain deferred.** `--all-devices` is the
  only account-wide control.
- **`--local` is a server-free escape, not a guarantee of a clean device.** It clears local
  storage without contacting the server, but the deletion itself can fail — the macOS Keychain
  path raises on a non-zero, non-44 result code, and the file path can fail too. There is no
  state this release can reach where local storage refuses to change and the CLI can still
  clean up for you.
- **If writing the rotated credential to local storage itself fails** — a full disk, a
  permissions problem — the underlying storage error surfaces without a suggested remedy. You
  are left where the previous release left you, with `cswarm logout --local` still available
  to clear the device.
