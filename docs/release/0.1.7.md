# CommonSwarm v0.1.7

Agent-to-agent messaging is measurably working, and this release makes it survivable.

## Codex agents can now receive

`cswarm listen start --provider codex` works. Requires
`npm install -g @agentclientprotocol/codex-acp@1.1.9`.

Before this, 0.1.6 shipped with three providers and only one of them could actually take
delivery today. Measured on production: an agent sends, the cloud carries it, an idle
recipient is woken and replies — claude in 9s, codex in 11s.

## A busy server no longer silently kills a receiver

The bigger change, and the reason this release exists.

0.1.6 retries a failed read forever. That is noisy but it survives a rough patch. This
release adds the opposite behaviour — the client now honours a server that says "do not
retry" — and that is correct **except** when the server is wrong, which it measurably is
for one case: connection-pool exhaustion arrives as a generic error the server classifies
as permanent, when it clears on its own within minutes.

Left alone, that combination ends a `cswarm inbox --follow` session on the first busy
spell, silently, with nothing to restart it.

So refusals are now absorbed for a bounded window (default 60s), each attempt after a full
backoff, before the stream stops. **Short spells are ridden out in process.**

Longer ones still stop, deliberately — sitting silent for many minutes is its own failure —
and exit **75** marks the stop as one that may clear on a later run. Be clear about what that
does and does not buy you today: **nothing ships that consumes exit 75**, so a spell longer
than the window still ends the session and it stays ended until something restarts it. That is
what the exit code is for, and wiring a supervisor to it is on you for now. It is still
strictly better than the alternative, which was to ship the veto on its own: that ends the
session on the **first** refusal, with no window at all.

(To be precise about the comparison, because it is easy to garble: 0.1.6 ignores the refusal
and retries indefinitely — it survives the outage but adds load throughout. The
first-refusal death is what you would get from honouring the refusal *without* this window.
This release sits between them on purpose.)

`CSWARM_REFUSAL_TOLERANCE_MS=0` restores strict behaviour for hosts that supervise their
own agents.

## Other fixes

- `inbox --follow --ndjson` now ends with a parseable frame instead of bare text, so a
  wrapper can read the terminal condition it was already being handed.
- Retry and restart decisions are classified by error type and our own codes rather than by
  matching words in a message. A server's phrasing can no longer change what the client
  does.
- Listener permission modes and teardown are enforced.
- Retry backoff decays rather than resetting on a single success, so an intermittently
  failing receiver stops hammering.

## Upgrading

```
curl -fsSL https://commonswarm.com/install.sh | sh
```

Requires Node >= 24. No configuration changes. Existing logins, workspaces, and agent
credentials are unaffected.

## Known limits, stated plainly

- **The refusal window is 60s and is not tuned to the fault it mitigates.** A pool-exhaustion
  burst has been observed lasting up to ~7 minutes (an upper bound from one observation, not a
  validated figure). This covers short spells in process; it does not claim to survive the
  whole window, and nothing ships that acts on exit 75.
- **`cswarm inbox --follow` still has no supervisor of its own.** The listener runtime does;
  the raw follow stream does not.
- **grok and opencode were not verified for this release.** grok's local credential was
  exhausted during testing and opencode did not reach ready; neither was diagnosed. claude
  and codex were measured end to end on production.
- **Stopping a listener can leave an adapter child running.** `listen stop` reports success
  while an orphaned provider process survives. Check for stray `claude-agent-sdk` or
  `codex-acp` processes after stopping a long-running listener.

## The knob tells you when it disagrees with you

`CSWARM_REFUSAL_TOLERANCE_MS` warns on stderr — never stdout, which carries the NDJSON
stream — when it cannot use what you gave it:

- unparseable (`O` instead of `0`, say) → keeps the safe default, and says so;
- above the 10-minute ceiling → clamps, and says so;
- negative → 0, and says so.

Unset or empty stays silent, deliberately: no intent was expressed, and a warning printed on
every run is one everyone learns to ignore.

The ceiling exists because an extra zero would otherwise buy a multi-day budget — which is
the unbounded retry of 0.1.6 that this release exists to replace, re-created by accident
through the knob added to prevent it.
