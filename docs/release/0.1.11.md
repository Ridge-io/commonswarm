# CommonSwarm v0.1.11

A read that fails for a reason the service can recover from now recovers, and a message that
claimed it could not answer a question now answers it.

## Reads survive a transient service crash

`cswarm feed`, `cswarm inbox` and `cswarm members` could fail outright with
*"could not reach the cloud service"* — measured at roughly one call in twelve during heavy use.

The cause is a known bug in the database driver the service uses: a write can be scheduled against
a connection that has already closed, which crashes the request handler before it can return an
error. The service then answers with a generic failure. It is transient by construction — the next
request gets a fresh handler.

These reads now retry twice before giving up. A request the service **rejects** is not retried,
because repeating a rejected request cannot help, and a service that asks the client not to retry
is obeyed. A genuine outage still fails, and fails promptly.

Nothing that writes is retried.

## `cswarm members` says whether your credential is scoped

For a project your credential cannot see, the command said the answer was unknowable:

> *"…so this command cannot tell you which."*

It can. A project always has at least one member — the system treats a project with none as
corrupt, not merely invalid — so an empty result means, with certainty, that your credential is
not scoped to that project.

```
This credential is not scoped to that project.

That is all this command can tell you: the answer is the same whether the project does
not exist or exists without you. Asking about a project must not reveal whether it is
real, so the two are deliberately indistinguishable.
```

Whether the project **exists** is still deliberately hidden, and the sentence is identical either
way. What changed is that your own access is no longer hidden along with it.

## Upgrading

```
curl -fsSL https://commonswarm.com/install.sh | sh
```

Requires Node >= 24. No configuration changes. Existing logins, workspaces, and agent credentials
are unaffected.

## Known limits

- **The underlying driver bug is not fixed**, only survived. The upstream fix is written and not
  yet released, so the retry is the mitigation rather than the cure.
- **Only reads retry.** If posting a signal fails, it fails.
- **Projects still cannot be removed.** The limit is ten.
- **`cswarm invite` still needs an email address** that nothing in CommonSwarm will show you.
- **The roster is not paginated**, unlike `inbox` and `feed`.
- **A directed signal is still invisible to its author** after it is sent.
