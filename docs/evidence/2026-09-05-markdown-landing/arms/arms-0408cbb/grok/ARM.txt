## Findings

### 1. Medium — spaced `---` after an open `ul` is still a list item

`site/src/lib/message-markdown.ts:256-257` says the `renderBlocks` order (break, then heading, then list, then table) stops `- - -` from being read as a list item. That check lives only at the `renderBlocks` entry (`478-481`). `renderList` (`312-335`) never calls `isThematicBreak`. `listMatch` accepts `- - -` and `* * *` as `ul` items because both start with `[-+*]` plus whitespace. `*` and `-` share `kind: "ul"`, so a marker change does not end the list.

Concrete inputs (measured):

| source | output |
|---|---|
| `- item\n- - -` | `<ul><li>item</li><li>- -</li></ul>` |
| `* item\n* * *` | `<ul><li>item</li><li><em> </em></li></ul>` |
| `* item\n- - -` | `<ul><li>item</li><li>- -</li></ul>` |

Controls on the same path that still work: `- item\n---` → `<ul><li>item</li></ul><hr>` (no space after the marker, `listMatch` fails). `1. item\n- - -` → `<ol>…</ol><hr>` (ol→ul kind change). `text\n- - -` → `<p>text</p><hr>`. `> a\n> - - -` → hr inside the quote (`renderBlocks` again).

The pin at `site/src/lib/message-markdown.test.mjs:341-357` only feeds standalone lines. It cannot fail for the list-continuation case.

### 2. Low — feed sibling gap omits `table` and `hr` as the following sibling

`site/src/components/app/LiveDashboard.astro:9542-9544`:

```css
.dashboard__message-markdown :where(p, ul, ol, blockquote, pre, table, hr) +
    :where(p, ul, ol, blockquote, pre)
```

Brain at `8728-8729` puts `table, hr` on both sides of `+`. The feed adds them only on the left, while `9538-9540` and `9641-9643` set `margin: 0` on `table` and `hr` (so the UA `hr` margin is gone too).

Sequence: a paragraph then a table or rule in the feed (`hello\n\n| a |\n|---|\n| 1 |`, or `hello\n---`). `p + table` and `p + hr` get no `margin-block-start`. `table + p` still does. The Brain panel has both classes, so it does not show the miss. The comment at `9596-9598` said a rule written for only one surface is a difference a reader would meet.

### 3. Low — budget comment is false for leftover budget

`site/src/lib/message-markdown.ts:532-536` says the table wants more cells than the whole message may spend, then sets `budget.cells = 0`. That is true only when the table itself is larger than 20_000. When table 1 uses 19_990 and table 2 wants 20, table 2 is over the remainder, the budget is zeroed, and a later 4-cell table also stays literal.

Measured: table 1 (9_994 body rows) renders; table 2 (10 body rows) renders alone; combined output has one `<table>` and the second table’s `| 3 | 4 |` stays text. The 20_000 cap still holds. The bound is stricter than the comment.

That list is not `MESSAGE_MARKDOWN_TAGS`. It drops `del`, `a`, `hr`, `ul`, `ol`, `li`, `blockquote`, `pre`, headings. A cell with `~~x~~` would fail this test even though `<del>` is allowed. The byte-identical `HOSTILE_INLINE_VECTORS` loop is the real control; this regex is a second, drifting claim.
