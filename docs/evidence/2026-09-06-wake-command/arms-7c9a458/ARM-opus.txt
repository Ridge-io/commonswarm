   `wake` is added inside the `freshOnly` record (command/index.ts:9194-9202), the same object
   that carries `agent_token` (:9194) and is spread only into the fresh result (:9216). A replay
   therefore returns neither `agent_token` nor `wake`. The client cannot see "two different
   answers" for a field it saw before, because on the fresh response the two travel together and
   on a replay both are absent — the existing, already-shipped contract for agent_token. For L4
   this is safe: a listener that replays a mint/renew must fall back to the inbox read (W3.1),
   which is the spec's stated learning path anyway.

   the rotation-on-revoke design requires exactly that, so this is preferable to echoing a stale
   topic — but it is an inconsistency between the claim and mint/renew shapes that the report does
   not name.
