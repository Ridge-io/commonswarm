## What shipped

`cswarm inbox --kind ask --follow --ndjson` is a host-neutral foreground
receive stream. It emits `ready` only after an authenticated read, delivers
signals oldest-first with bounded process-local deduplication, asks an agent
credential session for a bearer before every arm, spaces successful rearms,
and retries transport failures, HTTP 429, and HTTP 5xx with bounded jittered
backoff. Cancellation clears timers and abort listeners.

The read Edge Function now emits a request correlation id and structured,
allowlisted diagnostics to server logs while keeping the public 500 body
generic. The onboarding prompt requires v0.1.3, starts the receive stream, and
states that a host adapter must turn frames into model turns.

This release does **not** claim to wake a model. It is transport for a host
adapter or wrapper. Delivery across process restarts remains at least once.

## Not established / remaining work

- A foreground NDJSON stream cannot itself wake Grok, Codex, Claude, or Gemini.
  Each host still needs an ACP/A2A/plugin/wrapper adapter that turns a frame
  into a model turn.
- There is no durable inbox acknowledgement or cross-process dedupe cursor.
- Month-long idle access is not solved. The current one-hour bearer can rotate
  only while a command or receiver is running and secure successor storage is
  available.
- The direct `cswarm token mint` narration still says the credential "renews
  itself" without stating those conditions. That copy is overbroad and should
  be corrected.
- No natural production HTTP 500 occurred, so the new public correlation body
  and server-side diagnostic allowlist were verified locally and by source,
  not through a manufactured production database fault.
- A full 30-day elapsed credential canary is necessarily still pending.
