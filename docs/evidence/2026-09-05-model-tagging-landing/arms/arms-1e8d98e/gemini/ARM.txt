## Findings

**1. One vocabulary, generated sentences**
* `scripts/check-agent-trailers.sh`, line 1184: The error message retypes the family value as `CSWARM_AGENT_FAMILY=unknown` instead of deriving it from the vocabulary array or using a constant.
* `scripts/agent-trailers.sh`, line 989: The help text explicitly retypes the word `declared` (`recorded with source 'declared'`) rather than building the string using `$AGENT_TRAILER_SOURCE_DECLARED`.
* `docs/development/agent-trailers.md`, lines 360-363 and 411-414: These doc examples explicitly retype vocabulary values like `openai`, `unknown`, and `none`. 

This matters because retyped strings drift silently if the underlying vocabulary changes, violating the repo rule that enumerations must be generated. 

**2. Codex detector reads the oldest rollout (False `runtime-transcript`)**
* `scripts/agent-trailers.sh`, lines 800-804: 
The `for` loop globs Codex rollouts (`"rollout-"*"-${CODEX_THREAD_ID}.jsonl"`), which expand in lexicographical order (oldest timestamp first). Because the loop `break`s on the very first match, a thread spanning multiple rollouts will always read the *oldest* rollout file. If the model was changed mid-thread, the script signs the commit with a stale model but still confidently sets `Agent-Model-Source: runtime-transcript`. This results in a silent bad measurement that is not disclosed in the docs.

**3. False green in CI for grace-skipped commits**
* `.github/workflows/agent-trailers.yml`, lines 156-159:
The workflow only emits the warning annotation if the script's output contains `"nothing to check"`, which only occurs on an empty range (zero commits). However, if a range contains commits but *all* of them are skipped by grace, the checker exits 0 and prints `0 of N commit(s) checked`, which doesn't match the case pattern. The CI job will silently stay green without checking any commits and without issuing the warning annotation, leading a reader to misread the check as a passed audit.
