### Findings

1. `tests/p1-cli/chat-cli.test.ts` (Importing `CHANNEL_SUBCOMMAND_NAMES`) and `src/cli.ts:8099` (Unconditional `main()` execution)
**Reason:** In `src/cli.ts`, `main().catch(...)` executes unconditionally at module evaluation time without any guard (like checking if it's the main module). Exporting `CHANNEL_SUBCOMMAND_NAMES` from `src/cli.ts` and importing it in `tests/p1-cli/chat-cli.test.ts` triggers this execution during the test runner's initialization. Since the test runner's `process.argv[2]` will not match any valid CLI command (it will be the path to the test file), `main()` falls through to throwing a `UsageError`. The `.catch()` block handles this by printing `cswarm: unknown command ...` to `stderr` and setting `process.exitCode = 1`. This silently taints the test runner process, causing the test suite to always exit with code 1 (failure) even if all assertions pass.

- **channelSelectorKind / channelSelectorProblem:** Refuted. `channelSelectorKind` accurately checks `UUID_RE.test(selector)` before ever calling `channelSelectorProblem`.
