## Findings

**1. `channelSelectorProblem` names the shape rule for a reserved selector, which is the wrong remedy.**

`src/cloud/channels.ts:192-196`:

```
export function channelSelectorProblem(selector: string): string | null {
  return channelSlugProblem(selector) === null
    ? null
    : `That is neither a channel name nor a channel id. ${CHANNEL_SLUG_RULE_TEXT} ${CHANNEL_ID_RULE_TEXT}`;
}
```

`src/cli.ts:7471-7475` calls that for every non-UUID selector before `fileContext`, so `cswarm channel archive all-signals` and `cswarm channel rename all-signals mobile` never reach a lookup.

`channelSlugProblem("all-signals")` is not a shape miss. It returns `all-signals is reserved. Reserved names: all-signals.` (`src/cloud/channels.ts:144-147`). `channelSelectorProblem` throws that answer away and interpolates `CHANNEL_SLUG_RULE_TEXT` instead.

`all-signals` already satisfies that shape rule: lowercase letters, digits, hyphens, starts and ends on a letter, length 11. The caller is told to fix a rule they did not break. `cswarm channel create all-signals` still prints the reserved sentence. Rename/archive do not.

The comment at `src/cloud/channels.ts:188-190` says the reader is told the two rules that were tried and neither of the wrong ones. Three rules ran (id, shape, reserved). The reserved sentence is the one that fired. It is not in the output.

The reserved spawn at `tests/p1-cli/chat-cli.test.ts:676-678` only runs `channel create`. Archive/rename reserved selectors are untested, so this stays green.

This is the same wrong-remedy class as round 1's mistyped id, inside the function that was meant to fix it.
