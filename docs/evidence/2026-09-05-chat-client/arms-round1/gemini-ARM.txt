**FINDINGS**

1. `src/cli.ts:628`: **Em-dash in user-facing CLI output.** The usage block prints "deployment's operators — agents are encouraged...", violating the rule against em-dashes in CLI output.
2. `src/cli.ts:887-897`: **Dead code.** `runChannelArchive` attempts to catch a `ChannelCommandError` with code `channel_archived` to print "Nothing changed." However, `supabase/functions/command/index.ts` treats archiving an already-archived channel as a successful no-op (returns 200 OK), so this catch block is never reached.
3. `tests/p1-cli/chat-cli.test.ts:1359`: **Test passes vacuously.** The test "a reserved channel name is refused by name..." iterates over `client.RESERVED_CHANNEL_SLUGS`. If this array is empty (as in mutation M13), the loop executes zero times and the test passes without verifying the refusal behavior.

**REFUTATIONS**

- **Claim 1 (exactKeys compatibility):** Refuted. `ThinCommandClient.sendSignal` uses conditional spreads (`...(condition ? {} : { key: val })`) for the new chat keys. Un-set keys are completely omitted from the JSON payload rather than being sent as `undefined` or `null`, satisfying `exactKeys` on the edge.
- **Claim 2 (Typed enumeration & Bound completeness):** Refuted. The usage text in `src/cli.ts` manually types the list of accepted channel subcommands (`create, ls, rename, archive`) rather than building it from `CHANNEL_SUBCOMMANDS`. However, this is safely covered by the drift test "the usage text advertises every channel surface this build has". The bound stated in the constant drift test ("It does NOT prove the two modules export the same SET of names") is both true and complete, honestly stating that an added unshared constant cannot be detected by a shared list.
- **Claim 3 (D-053 compliance):** Refuted. `channelCommandError` correctly branches on HTTP status (e.g., 403, 426) and only uses the server message presence to pass it through, not branching on its prose. `unknownChannelReadMessage` branches on the stable server code `error.error !== "channel_not_found"`. Neither branches on message prose.
- **Claim 4 (Thread replies):** Refuted. Forcing `in_reply_to` to null under `--thread` correctly prevents a 400 from the server's `chatSignalShapeProblem` (which refuses bodies carrying both keys). Suppressing `replyRefusalHint` is the right call because a 403 on an unaddressed open thread reply is never due to the private reply rule (which requires the caller to be the addressee).
- **Claim 5 (Read paths breaking & Undefined downstream):** Refuted. Both `humanSignals` and `agentSignalPage` use conditional spreads, so requests without a channel filter are unchanged and will not break. `normalizedSignalQuery` properly uses `...query` to pass the new fields through. Downstream consumers do not evaluate `record.channel_id === undefined` as a value, and JSON serialization safely drops it.
- **Claim 6 (Agent channel list):** Refuted. The claim is true: `supabase/functions/read/index.ts` only answers resources for `signals`, `members`, `files`, `delivery_receipts`, and `renewal_grants`. It does not have a channels resource, gating it correctly on `auth.uid()`. Deliberately NOT enumerating the allowed resources in the refusal sentence avoids creating an unbacked typed enumeration that would drift, and it remains actionable by directing the user to sign in or use a specific channel slug.
- **Claim 7 (Refusal ordering):** Refuted. The ordering inside the CLI subcommands (Positional arguments -> `assertShape` flag check -> Slug string rule -> Network check) matches the edge's `channel_rename` validator (exactKeys -> UUID regex -> Slug string rule). No purely local refusal is paid for with a network call.
- **Claim 8 (Tests pass for wrong reason):** Refuted (partially, but the core design holds). While some tests could pass vacuously if constants were completely emptied (as noted in findings), the positive control marker (`--agent-token-file /nonexistent/nope.json`) works as intended. If a feature fails to reject bad inputs early (like an unknown flag), the CLI will proceed to file-loading, throw `ENOENT`, and fail the assertion correctly.
- **Claim 9 (Anything else):** See findings above for the em-dash and dead code.

VERDICT: FAIL
