## 4. `parseSignalRecipients` — PASS

Refusals are the right ones:

| Rule | Why |
|---|---|
| Unknown key / not exactly `id,kind,position` | Fail closed on a shape this reader does not own |
| Repeat position or id | DB unique; a duplicate is corruption |
| No contiguity / sort check | DB + view own that; re-deriving it would drop a valid row |

The view emits `jsonb_build_object('kind','id','position')` or `'[]'` or a one-entry scalar fallback. Parser sorts keys, so JSON key order does not matter. I could not build a shape that view actually emits that this refuses.

Absent vs `[]` stays distinct: `undefined` → omit the field; `[]` → `{recipients:[]}`. `cswarm feed --json` goes through `signalReadJsonPayload` → the `SignalRecord`s as-is, so JSON has no key vs `"recipients":[]`.

Malformed set: `parseSignalRecord` throws. Hook and resume use `tolerateMalformedRows: true, maxMalformedRows: 3` and skip the row. Arrival-watch does **not** tolerate, so one bad set takes down the watch. That is the right blast radius for a guard that must not emit a page it cannot classify. Same as any other malformed field on that path.

