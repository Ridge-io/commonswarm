1. **Tenancy and authorization.** PASS. The `EXISTS` arm inside `hydrateDeliveryRefs` and the `expired` ack filter on `addressed.signal_id = s.id AND addressed.workspace_id = s.workspace_id`. Since the outer query strictly binds `s.workspace_id = args.workspaceId`, the recipient row's workspace is forced to match the requested workspace. It cannot leak across workspaces or allow an unaddressed agent to read the signal.
2. **`to_agent` now means something different on this wire than on a feed read.** PASS. `parseDeliveryRow` in `src/cloud/delivery.ts` is the only consumer of a hydrated delivery's `signal.to_agent`. Its validation (`signal.to_agent !== expected.principalId`) changes meaning to "is this delivery's recipient me?", which correctly preserves the "was this addressed to me?" intent. This behavior is documented inline and is not silently changed. The listener journal fingerprint (`immutableSignalFingerprint`) and the main-route projection (`pendingMainEntry`) do not consume `to_agent` at all. Receipts (`renderedBroadcastIds`) check `to_agent === null`, which remains accurate since hydrated deliveries always have a non-null `to_agent`. 
3. **Double wake and lost wake.** PASS. The primary key `(signal_id, recipient_agent_principal_id)` is the only unique constraint on `swarm.signal_deliveries`. The `signals` trigger (firing first via foreign key requirement) and the `signal_recipients` trigger will both insert a row for position 0. The second insert simply hits the primary key conflict and is safely ignored by `ON CONFLICT DO NOTHING`. There are no other unique constraints or deferred constraints to be swallowed.
4. **The three new refusal clauses.** PASS. The `until > statement_timestamp()` check is unreachable via the edge because `postSignal` sets `created_at = statement_timestamp()` and the table enforces `until > created_at`; the comment accurately states this only catches backdated direct inserts. `revoked_at IS NULL` correctly prevents unclaimable rows from filling the queue. The self-address refusal is a genuine behavior change, as nothing in the command edge (`postSignal`) previously prevented an agent from waking itself.
5. **Concurrency and the claim/ack paths.** PASS. The outstanding-lease cap, `pending_delivery_count`, and `oldest_pending_at` are all aggregated per `recipient_agent_principal_id`, meaning concurrent listeners for different recipients are fully isolated. `SKIP LOCKED` operates per unique delivery row. Nothing assumes a single listener per signal.

An old 0.1.55 client correctly accepts a new claim response because it ignores the unknown JSON fields and checks the updated `to_agent` value. The new client does not refuse valid capable server responses because the edge guarantees `recipient_count >= 1` and `recipient_position < recipient_count`.
