## 4. `applyChannelFromUrl(workspaceId)` and `syncChannelUrl` after every open — HOLD

Mismatch rule:


Then `syncChannelUrl` writes `?w=` for `activeWorkspaceId` and `?c=` from `unknownChannelId ?? activeChannelId`.

| Open path | Address bar after a successful open |
|---|---|
| Menu (`3175`) | `?w=` this workspace; previous workspace’s `?c=` dropped if `?w=` disagreed |
| Create workspace (`5954`) | same; old `?c=` dropped |
| Close-and-fall-through (`5095`) | `?w=` next; old `?c=` dropped (it belonged to the closed workspace) |

| Roster reload (`1836`, `1951`, `3409`, `3458`, `3501`) | same workspace; `?c=` kept |

There is no `popstate` handler. A link is applied only at boot (or a full reload). An in-app menu switch is not “following a link”; dropping that `?c=` is the round-3 fix.

### 2. A filter that replaces the predicate

Live narrowing is the query. `signalPage` adds `eq("channel_id", channelId)` on top of `workspace_id` and `until` (`2028-2034`).
