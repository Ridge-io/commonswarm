1. `channelListFailed` can become stale. It is only set during the initial workspace load in `activateWorkspaceView`. If a user creates or modifies a channel, `refreshChannels` updates the `channels` array but does NOT update `channelListFailed`. If the initial load failed (`true`), it remains `true` even after a successful refresh, incorrectly showing "The list of channels did not load". Additionally, if `refreshChannels` fails, it throws an unhandled promise rejection without updating `channels` or `channelListFailed`, allowing a case to reach the "no channel here" branch (`channelListFailed === false`) even when the latest list fetch did in fact fail.
2. There is no third path to a post while `unknownChannelId` is set. The composer form hides itself, and the `submit` event listener correctly intercepts and refuses the post (line 6784). Pressing `Enter` or clicking the composer retry button explicitly triggers `requestSubmit()`, which fires the exact same `submit` event and is caught by the same check. Drag-and-drop only stages files without submitting. `postBrowserSignal` is not called anywhere else.
3. `activateWorkspaceView` clears `aria-current` from `[data-channel-place]` buttons for non-signals views. When switching back to `"signals"`, the mark comes back correctly for readable channels because `renderChannelHead()` calls `syncChannelCurrent()`. However, if the current view is an unresolved channel (`unknownChannelId !== null`), `syncChannelCurrent()` unconditionally removes `aria-current` from all `[data-channel-place]` buttons. Because the `all-signals` button is a `[data-channel-place]`, it loses the `aria-current` mark that `activateWorkspaceView` had just applied to it. This leaves the desktop rail with NOTHING marked as current.
4. The argument for `COMPOSER_DRAFT_SCOPE` is correct: the localStorage draft scope uses the frozen literal `"all-signals"` (the exact value of the old `COMPOSER_STREAM` constant). Tying it to `ALL_SIGNALS_SLUG` would orphan existing browser drafts the moment the UI slug changes. Furthermore, `ALL_SIGNALS_SLUG` is defined in `site/src/lib/channels.ts` without relying on browser globals, making it perfectly safe to reach from the Astro frontmatter (Node/SSR environment).
5. Yes, you can still type `#` into a thread reply. The client-side `#` parser has been removed entirely since bodies legitimately contain `#`. For thread replies, the client sets `threadRootId` and explicitly omits the `channel` field. Because `channel` is `undefined`, the server-side validation (`threadRoot !== null && channel !== undefined`) passes cleanly, meaning the server does not refuse the post.
6. The `activeWorkspaceId` variable is bound safely. The loop checks capture the module-level `activeWorkspaceId` before an asynchronous fetch and compare it afterward, cleanly dropping stale network responses if the workspace changed mid-flight. Because browser tabs execute in completely isolated JavaScript contexts, opening two tabs simply creates two independent `activeWorkspaceId` variables that cannot interfere with each other.
