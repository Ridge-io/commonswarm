1. **Trace `createBrainTopicReader` (Workspace switch & `sampleMode`):**
Yes, a control can authorize opening a topic the new workspace does not hold. In `readBrainTopics`, if the workspace changes mid-await (`workspaceId !== activeWorkspaceId`), or in the `read` wrapper if `sampleMode` is true, the function returns early *without throwing*. The injected `read` promise thus resolves successfully. `createBrainTopicReader` then sets `fresh = true` without updating the `files` array. A concurrent or subsequent click evaluates `listIsFresh` as true, and uses the old workspace's `brainTopicNames()` snapshot to incorrectly authorize opening a topic that the current workspace does not hold.

No XSS or injection paths were found. `linkifyBrainTopics` safely traverses text nodes and uses `document.createElement("button")`, `textContent`, and `dataset` instead of modifying `innerHTML`. 3. **Attack the token run and gates:**
- **Unintended link:** The token run regex `/[A-Za-z0-9._~\-/\\@:?#=&%+]+/gu` explicitly omits semicolons (`;`) and commas (`,`), which are valid sub-delimiters in URLs. A real agent writing `See https://example.com/api;topic=commonswarm-roadmap` or `Check https://example.com/page,commonswarm-roadmap` will cause the run to split at the punctuation. `commonswarm-roadmap` will subsequently match and inject a clickable button right into the middle of a plain-text URL, breaking copy-pasteability.
- **Missed link:** A real agent writes: `The plan is in the \`roadmap.\` topic.` The `codeSpan` string is exactly `"roadmap."`. While `resolveRun` properly trims the trailing punctuation to yield a matched topic of `"roadmap"`, `isLinkable` performs a strict exact-match check (`codeSpan.trim().toLowerCase() === topic`), so `"roadmap." === "roadmap"` evaluates to false. The intended link is completely missed.

4. **Does `readBrainTopics` overwriting `files` break panels?:**
Yes. The comment explicitly states: "A background read has no business rebuilding the Files list or the Brain pane underneath a reader who is using them". However, the logic does the exact opposite:
```typescript
const view = app.dataset.channelView ?? "";
if (view === "files") renderFiles();
if (view === "brain") renderBrain();
```
It rebuilds the panels *only* when the reader is currently looking at them. If a user is actively typing to rename a file in the Files panel (`view === "files"`), a background read will complete, fire `renderFiles()`, and completely wipe out their active state and DOM selection.
