1. **Trace it (The Race Condition)**: A control CAN open a topic the workspace no longer holds, breaking the core guarantee of this iteration. In `openBrainTopic`, the code calls `await refreshBrainTopics(true)` to guarantee a fresh read before evaluating `brainLinkClickOutcome`. However, `refreshBrainTopics` includes an `in-flight` guard (`if (sampleMode || !workspaceId || brainTopicRefreshInFlight) return;`). If the periodic feed tick (`refreshBrainTopics(false)`) is currently in flight when the user clicks a topic, `refreshBrainTopics(true)` will return synchronously and immediately *without awaiting the network response*. `brainTopicNames()` will then be evaluated against the old snapshot. If the topic was deleted on the server but still exists in the snapshot, `brainLinkClickOutcome` returns `{ kind: "open" }`, passing a deleted topic to `brainView.open` which will fail inside the download exactly as it did in Round 2.
2. **XSS / DOM-clobbering**: None. The pass strictly operates on `nodeType === 3` (text nodes) of the already-sanitized tree, using `createElement` and `textContent`. It does not touch `innerHTML` or introduce new elements that could bypass the sanitizer allowlist. 
3. **Attack the token run/gates**: The token run `[A-Za-z0-9._~\-/\\@:?#=&%+]+/gu` successfully absorbs URL and path characters. If an agent writes `"I modified /etc/shared-host.conf"`, it correctly will not trigger a link because the run captures the slashes and `.conf`. The equality gate on backticked bare words correctly handles `"Wait for the next `releases`."`

If a user is midway through renaming a file in the Files panel or has an unsaved topic open in the Brain panel, a background feed tick detecting a change from another user/agent will forcefully re-render those panels.
