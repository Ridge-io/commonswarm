## 2. Is `suspension_active` the single definition?

**Attempted refutation:** grep every “paused?” decision.

- preflight `IF grant_row.suspension_active` (~line 273)
- use recorder `AND NOT grant_row.suspension_active`
- successor fence `IF grant_row.suspension_active`

- both read functions `CASE WHEN grant_row.suspension_active THEN grant_row.suspended_at END`

The command edge remaps the same way (`CASE WHEN g.suspension_active THEN g.suspended_at END AS grant_suspended_at`).

**Second answer still exists in the reducer.** `src/protocol/workspace-commands.ts` (and the generated `supabase/functions/_shared/protocol.js`) still does:

That is a second predicate. It is only consistent because the edge stuffed the *effective* timestamp into `grant.suspended_at`. The migration’s catalogue control greps `pg_proc` for `suspension_active` and never looks at `command/index.ts` or the reducer.

Not the killing defect, but the “ONE definition” claim is overstated.

## 3. Idle clock restart at resume

Walk a grant with `last_used_at` 20 days ago, `resumed_at = now()`:

```
idle_since := COALESCE(last_used_at, created_at);          -- 20d ago
IF resumed_at IS NOT NULL AND resumed_at > idle_since THEN
  idle_since := resumed_at;                                -- now
END IF;
IF kind = 'standing' AND idle_since < statement_timestamp() - interval '14 days'
```

`now < now - 14 days` is false, so it does **not** re-pause. Next preflight returns NULL. Proven from SQL (`20260904000001_standing_grant_resume.sql:283-289`). The p1-local test asserts this with `last_used_at` still old.

**This check holds at the SQL layer.** It does not save the edge.

## 8. What broke / the killing defect

`swarm.resume_renewal_grant` returns NULL on success (`20260904000001_standing_grant_resume.sql`, `RETURN NULL`). The edge:

```5712:5720:supabase/functions/command/index.ts
  const outcomeRows = await tx<{ resume_outcome: string | null }[]>`
    SELECT swarm.resume_renewal_grant(...) AS resume_outcome
  `;
  const resumeOutcome = outcomeRows[0]?.resume_outcome ?? "renewal_resume_forbidden";
  if (resumeOutcome !== null) {
    return await refuse(..., `renewal_resume_${resumeOutcome}`, forbidden, ...);
```

`null ?? "renewal_resume_forbidden"` is `"renewal_resume_forbidden"`. After that, `resumeOutcome !== null` is **always true**. Contrast the existing preflight pattern: `preflight[0]?.code ?? null`, which preserves SQL NULL.

Same `db.begin` callback: a 403 return **commits**. So the first call actually resumes the row, then 403s; the CLI throws `CommandHttpError(403)`; a retry gets `renewal_grant_not_suspended` and 403s again. No idempotency key is written. Audit says `renewal_resume_renewal_resume_forbidden`.
