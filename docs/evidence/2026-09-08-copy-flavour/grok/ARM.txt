## (1) After preventDefault() + setData('text/plain'), can any path from this block still put text/html on the clipboard?

Handler, `site/src/components/connect/AgentConnect.astro` `#wire()`:

```
this.#q<HTMLElement>('[data-slot="prompt"]')?.addEventListener("copy", (event) => {
  const clipboard = (event as ClipboardEvent).clipboardData;
  if (!clipboard || !this.#prompt) return;
  clipboard.setData("text/plain", promptCopyPayload(window.getSelection()?.toString() ?? "", this.#prompt));
  event.preventDefault();
});
```

Clipboard API contract (W3C WD, §6.1 override copy, §8.1 copy action, “fire a clipboard event”, “write content to the clipboard”):

- For copy/cut the event’s DataTransfer is created with an empty items list (read/write).
- If the event is not canceled, the UA copies the selection and *should* create both text/html and text/plain.
- If it *is* canceled, the UA writes only the items on that DataTransfer. text/plain is placed as plain text; text/html is placed only if that type is in the list.

This handler never calls `setData("text/html", …)`. Grep of `site/` found no other `addEventListener("copy"` / `oncopy`. After the successful branch (setData text/plain then preventDefault), the spec write algorithm therefore has no HTML item to put on the OS clipboard.

Replica of that branch (node, fake DataTransfer): successful copies store only `{ "text/plain": … }` and set `prevented: true`.

Paths that do **not** reach preventDefault (so they are outside the “after preventDefault + setData” clause):

- `clipboardData` null, or `#prompt` null/empty: early return. Default UA copy can still write HTML. Replica: no throw, `prevented: false`.
- The copy event never targets the `<pre>`. The `<pre>` is not an editable context. Spec target for non-editable copy is the *focused node*, or body. A selection inside the pre while focus is elsewhere fires on the focused node, not on the pre, so this listener never runs. The pre has `tabindex="0"`, so a click-to-select typically focuses it; that is the intended path, not a proof for every UA.
- `cut` and `dragstart` are not handled. Spec cut on a non-editable context does not copy if not canceled. Drag of a DOM selection still puts text/html on the drag store. Out of the copy-event claim.

Could not refute the spec contract for the branch that actually calls preventDefault + setData('text/plain'). Could not establish that a live UA does not also synthesise `public.html`.

## (2) promptCopyPayload is byte-for-byte; empty/whitespace fallback cannot swallow a one-character selection

```
export function promptCopyPayload(selectionText: string, fullPrompt: string): string {
  return selectionText.trim().length > 0 ? selectionText : fullPrompt;
}
```

`trim()` is only the condition. The returned value is whichever argument the ternary picks, with no replace, encode, or trim of that value.

Node probe of the shipped function:

- `"_"` / `"a"` → same one character (not the fallback).
- `"  x  "` → `"  x  "` (padding kept).
- `""` and `"   \n\t "` → full prompt.
- `"\u00a0"` (NBSP) → full prompt, because JS `trim` strips Unicode whitespace. That is the whitespace fallback, not a one-character token from the prompt JSON.
- Hostile JSON with `_` and a URL returned identical.

Cannot refute (2) for a non-whitespace one-character selection. The tests do not pin that fact (see (5)).
