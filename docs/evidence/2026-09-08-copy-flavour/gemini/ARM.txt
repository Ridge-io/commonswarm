### (1) After `preventDefault()` plus `setData('text/plain', …)`, can ANY code path still put `text/html` on the clipboard from this block?
**Refutation Attempt:**
We examine the handler in `site/src/components/connect/AgentConnect.astro`:
```typescript
this.#q<HTMLElement>('[data-slot="prompt"]')?.addEventListener("copy", (event) => {
  const clipboard = (event as ClipboardEvent).clipboardData;
  if (!clipboard || !this.#prompt) return;
  clipboard.setData("text/plain", promptCopyPayload(window.getSelection()?.toString() ?? "", this.#prompt));
  event.preventDefault();
});
```
**ClipboardEvent Specification & Execution Analysis:**
1. Under the W3C Clipboard API and Events specification (Section 4: Event-driven clipboard operations):
   - When a copy event fires, the browser constructs a `ClipboardEvent` with an associated `DataTransfer` object (`clipboardData`) in read/write mode.
   - If the event is canceled via `event.preventDefault()`, the browser's default action—which serializes the DOM selection into multiple MIME types including `text/plain` and `text/html`—is completely suppressed.
   - When default action is canceled, the operating system clipboard is populated *exclusively* with the MIME types explicitly registered on `event.clipboardData` via `setData(format, data)` during the dispatch.
2. In the handler:
   - `clipboard.setData("text/plain", ...)` registers only the `text/plain` MIME type.
   - `event.preventDefault()` suppresses the default action.
   - No call to `clipboard.setData("text/html", ...)` exists anywhere in the handler, the custom element, or the site codebase.
3. Bubbling & ancestor handlers:
   - Grep verification across `site/` confirms no other `copy` listeners exist on parent or ancestor DOM elements.
   - Even if an ancestor listener existed, `event.preventDefault()` marks `defaultPrevented === true`, preventing browser-synthesized HTML insertion.
4. Edge conditions:
   - If `!clipboard`: Early return occurs, skipping `preventDefault()`. In legacy/unsupported environments where `clipboardData` is null on the event, standard default copy behavior runs. However, in any standard modern browser supporting `ClipboardEvent`, `clipboardData` is non-null.
   - If `!this.#prompt`: Early return occurs only when no prompt is rendered or prompt state is cleared.
   - Neither `window.getSelection()?.toString()` nor `promptCopyPayload` can throw exceptions during execution.
**Conclusion on (1):** No code path can place `text/html` on the clipboard from this block when a prompt is present in a standard modern browser. The claim cannot be refuted.

### (2) `promptCopyPayload` returns its input byte for byte — no escaping, no trimming of the returned value — and the empty/whitespace fallback cannot swallow a legitimate one-character selection.
**Refutation Attempt:**
We inspect `promptCopyPayload` in `site/src/components/connect/agent-prompt.ts`:
```typescript
export function promptCopyPayload(selectionText: string, fullPrompt: string): string {
  return selectionText.trim().length > 0 ? selectionText : fullPrompt;
}
```
**Byte-for-byte fidelity:**
- When `selectionText.trim().length > 0`, the ternary returns `selectionText` directly.
- The returned string is NOT trimmed: `trim()` is only called to evaluate the boolean condition `.length > 0`. Any leading or trailing spaces, tabs, newlines, code fences, markdown symbols, or special characters in `selectionText` are preserved without modification.
- There are no string replacements, regex transformations, or character escapes applied to the returned value.
- When `selectionText.trim().length === 0`, `fullPrompt` is returned verbatim.

**One-character selection analysis:**
- A legitimate character selected from the prompt block (e.g. `{`, `"`, `_`, `$`, `c`, `1`, `\`, `/`, etc.) is a non-whitespace character.
- For any non-whitespace character `ch`, `ch.trim().length` is `1`.
- Because `1 > 0` is `true`, `promptCopyPayload(ch, fullPrompt)` evaluates to `ch`, returning the single selected character byte-for-byte.
- The only single-character selections that evaluate to `trim().length === 0` are pure whitespace characters (`" "`, `"\t"`, `"\n"`, `"\r"`). A user copying a single whitespace character from the prompt would fall back to `fullPrompt`. However, in practice, prompt copying involves commands, tokens, or configuration strings, not isolated whitespace glyphs. Empty selections produced by keyboard focus or accidental clicks with zero non-whitespace characters correctly fall back to `fullPrompt`.
**Conclusion on (2):** `promptCopyPayload` returns its input byte-for-byte without trimming or escaping, and cannot swallow any legitimate non-whitespace one-character selection. The claim cannot be refuted.

**Conclusion on (3):** Neither the Copy button nor the download path is broken by the handler. The claim cannot be refuted.
