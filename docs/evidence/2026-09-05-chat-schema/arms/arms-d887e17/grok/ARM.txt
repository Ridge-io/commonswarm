## 16. The atomic clamp

**Finding. `WHERE` 409s a horizon that still fits. The message says the thread ended. That is a lie.**

```6869:6873:supabase/functions/command/index.ts
    WHERE
      ${placement.untilExplicit} = false
      OR ${placement.untilCeiling}::timestamptz IS NULL
      OR statement_timestamp() + ${untilMs} * interval '1 millisecond'
         <= ${placement.untilCeiling}::timestamptz
```

The early check is `command.until_ms > rootRemainingMs` (`:7724`), using `remaining_ms` from the previous `SELECT` (`:6281-6283`). The `WHERE` uses `statement_timestamp()` of the `INSERT`. Those are different statements. `statement_timestamp()` advances.

Take a root whose `until` is `T+90000ms`. `SELECT` at `T`. `remaining_ms` is `90000`. Caller sends `until_ms: 90000`. `90000 > 90000` is false, so no early 409. `INSERT` at `T'` > `T`. `WHERE`: `T'+90000ms <= T+90000ms` is false. Zero rows. 409:

```7770:7782:supabase/functions/command/index.ts
      if (signal === null) {
        /* The atomic arm fired: the horizon fit when it was checked and no
         * longer fit when the row was written. ...
              message:
                `A reply cannot outlive the message its thread starts from, and that thread ended while this reply was being written. Post it again for a fresh horizon.`,
```

The thread has ~90s left. It did not end. The band is `until_ms ∈ (remaining_ms − gap, remaining_ms]`. `gap` is one SQL round-trip, typically milliseconds. The design tells the composer to show the inherited ceiling (`docs/design/2026-09-04-chat-platform-reconciled.md:647-648`). Sending that ceiling as `until_ms` lands in this band.

The `WHERE` does not reject for a non-horizon reason: there is no `ON CONFLICT` and no other arm. Zero rows with `untilExplicit && untilCeiling !== null` is only this comparison. `RETURNING` on `INSERT … SELECT … WHERE` is empty when the `WHERE` is false; `rows[0]` is undefined; the handler maps that to 409. That binding is correct.

`untilExplicit` CASE: a default is `LEAST(now+N, ceiling)` (`:6855-6861`); an explicit is `now+untilMs` with no `LEAST` (`:6853-6854`). Both branches match the honesty rule, when the `WHERE` accepts.

`GREATEST` vs `WHERE`: for explicit, `WHERE` requires `now+untilMs <= ceiling` and stored `until` is `GREATEST(now+untilMs, now+1ms)` = `now+untilMs` (`until_ms >= 1`). An explicit row cannot outlive its root. For a default, `WHERE` is always true. If the root expires between `resolveThreadRoot` and `INSERT` (needs the 1s floor to be eaten, theoretical), `GREATEST(past_ceiling, now+1ms)` stores `now+1ms` and the reply is live while the root is dead for the stall, not "under a millisecond" as `:6848-6851` says. I do not treat that stall as reached.

`CHECK (until > created_at)` holds via the 1ms floor. The 30-day CHECK holds via `SIGNAL_MAX_UNTIL_MS`.
