## 4. Thread clamp

**Finding. The explicit-`until_ms` refusal uses the wrong clock. Silent shorten is reachable.**

The design remaining window is `root.until - statement_timestamp()` (`docs/design/2026-09-04-chat-platform-reconciled.md:638-643`). The handler uses the JS wall clock:

```7622:7624:supabase/functions/command/index.ts
      if (rootUntil !== null && command.until_ms !== undefined) {
        const remainingMs = rootUntil.getTime() - Date.now();
        if (command.until_ms > remainingMs) {
```

The insert then clamps with Postgres time (`command/index.ts:6775-6780`):

`LEAST(statement_timestamp() + untilMs * interval '1 millisecond', COALESCE(untilCeiling::timestamptz, …))`

`untilCeiling` is `rootUntil.toISOString()` (`:7646`).

Concrete case: Postgres time `T`. JS clock 2s behind. Root `until` is `T+5s`. JS `remainingMs` is 7000. Caller sends `until_ms: 6000`. `6000 > 7000` is false, so no 409. SQL `LEAST(T+6s, T+5s)` stores `T+5s`. The caller asked for 6s and got 5s. That is the dishonest branch named at `:7613-7616` and in the design at `:642-643`. Deno and Postgres do not share a clock. The remaining window can be milliseconds (`design:647`). Tens of milliseconds of skew is enough.

SQL `LEAST` still stops a reply from outliving the root. `CHECK (until <= created_at + interval '30 days')` still holds: `until_ms` is capped at 30 days (`command/index.ts:553,1768-1771`) and the ceiling is an existing `until`.

`CHECK (until > created_at)`: `resolveThreadRoot` requires `until > statement_timestamp() + interval '1 second'` (`:6422`). The gap from that `SELECT` to the `INSERT` is JS only. A 1s stall plus a root just above the floor is a theoretical 500. I do not treat that as reached.
