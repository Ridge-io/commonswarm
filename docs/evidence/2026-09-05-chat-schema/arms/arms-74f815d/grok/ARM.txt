### 4 / 11 / 16 / 22. The clamp

No finding that a stored reply can outlive its root, or that `CHECK (until > created_at)` / the 30-day CHECK fires on a thread insert.

The CTE computes one `until_value` (`command/index.ts:6883-6895`). The WHERE tests that same value (`:6926-6928`). `statement_timestamp()` is stable inside one statement, so CTE and WHERE agree.

- Explicit: `now + untilMs`, then `GREATEST(..., now+1ms)`. Not `LEAST`-clamped. If it no longer fits, WHERE returns zero rows.
- Defaulted: `LEAST(now+default, ceiling)`, then the same floor. If the floor raises the value past the ceiling, WHERE refuses rather than storing it (`:6939-6946`).

Equal to the ceiling is allowed (`<=`). That is not outliving. `GREATEST(..., now+1ms)` keeps `until > created_at`. A reply clamped to a live root is inside the root's 30-day window, so the 30-day CHECK does not fire.

Zero rows with `untilCeiling !== null` become 409 (`:6946`, `:7828-7857`). Zero rows with a null ceiling throw; that WHERE arm is `ceiling IS NULL OR ...`, so a non-thread insert cannot take it.
