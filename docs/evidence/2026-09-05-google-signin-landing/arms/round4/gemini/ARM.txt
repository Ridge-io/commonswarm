### Findings

**1. Typed Enumeration in Code**
- **File & Line**: `site/src/lib/commonswarm.ts`, Line 1708
- **What breaks**: The function `signInWithGitHub` explicitly names the provider in a string literal (`await signInWithProvider("github", redirectTo);`). The documentation in `auth-providers.ts` explicitly claims "Nothing else may name a provider in a string literal." This hardcoded function is a typed enumeration that will drift if GitHub is ever removed from `AUTH_PROVIDERS`.
- **Blocks landing**: Yes.

**2. Control Fails for Wrong Reason**
- **File & Line**: `site/src/components/auth/provider-buttons.observer.test.ts`, Lines 811-814
- **What breaks**: The control `"a provider this build does not render is absent from every page's copy"` uses `copyOf(html)` to strip tags and tests the remaining raw text. If a provider's name is used in a non-sign-in context (e.g., a site footer stating "View our source code on GitHub"), disabling that provider will fail the build because its name still appears in the page text. 
- **Blocks landing**: Yes.

**3. Incomplete Scan for Hand-Written Buttons**
- **File & Line**: `site/src/components/auth/provider-buttons.observer.test.ts`, Line 1014
- **What breaks**: The regex `/<button[^>]*\bdata-signin|setAttribute\(\s*["'`]data-signin/` misses multiple injection routes. It fails to catch anchor tags (`<a data-signin-provider>`), framework components (`<Button>`), and the DOM dataset API (`element.dataset.signinProvider = "..."`).
- **Blocks landing**: Yes.

**4. Decoration Control**
- **File & Line**: `site/src/components/auth/provider-buttons.observer.test.ts`, Lines 865-872
- **What breaks**: The control `"the enforcement accepts every rendered id and refuses anything else"` is pure decoration. It parses IDs from buttons that were mechanically mapped from `AUTH_PROVIDERS` inside `ProviderButtons.astro`, and asserts that `authProvider(id)` can find them in `AUTH_PROVIDERS`. This effectively just tests that `Array.find` works on the array the items were generated from.
- **Blocks landing**: No.

**5. Omission of Enabled Providers**
- **File & Line**: `site/src/lib/auth-providers.ts`, Line 1547
- **What breaks**: `providersFromSettings` iterates via `AUTH_PROVIDERS.filter((provider) => flags[provider.id] === true)`. If the deployment reports an OAuth provider not in `AUTH_PROVIDERS` as `true` (e.g., Apple or GitLab), it is omitted. This refutes the claim in the design document that "The code renders whichever OAuth providers the deployment reports as enabled" (it actually only renders the subset it is hardcoded to recognize).
- **Blocks landing**: No (the behavior is safe, but the documentation claim is false).
