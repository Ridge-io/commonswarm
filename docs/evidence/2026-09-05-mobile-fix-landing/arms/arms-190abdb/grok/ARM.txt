`scrollComposerCaretIntoView` (`DIFF.patch` 1069–1088): end-of-text uses `scrollHeight` and returns. Section 7 is right. Mid-text counts hard `\n` only; the comment already says a caret in a long wrapped paragraph can land a line off.

## 7. The new clearance rule and its harness

HTML order is toolbar, then `.dashboard__feed-more`, then `ol.dashboard__feed` (`LiveDashboard.astro:603–620`). Adjacent siblings, no wrapper. Show/hide is `more.hidden = !signalHasMore` (`:3942`). `.dashboard [hidden] { display: none !important; }` (`:6509–6511`), so `:not([hidden])` is the right test. No CSS `display: none` on `.dashboard__feed-more` except the UA/`[hidden]` rule. The 36rem block does not override the sibling rule (`DIFF.patch` 1584–1586). 320px is inside `max-width: 52rem`. The rule reaches both.

Harness (`DIFF.patch` 2135–2209, 2374–2423): `more=1` sets `.hidden = false`. Positive control: `feedMore !== null && height > 0`. The off variant must be `null`. Padding must be `"0px"` with the button and not `"0px"` without it. Gap `< 20`. If the knob did nothing, the node starts `hidden` in markup and the first assert fails. If the sibling rule is missing, padding stays `--feed-band-height` (52px) and both the padding assert and the gap assert fail. The case cannot pass while the double pad is back. Gap `< 20` would allow a 19px leftover; `"0px"` is the tight control.

The new case is only measured at 390×844. `assertPhoneHeaderRule(withMore, 390)` checks the first *message* against the band, not the load-older button. If `.dashboard__feed-more` lost its `padding-block-start` while the sibling rule stayed, the button would sit under the pill and the first row could still clear it because `.dashboard__feed-more` still has `padding-block-end: var(--s-10)` from the base shorthand (`LiveDashboard.astro:9199–9206`). That is not the defect this case pins.
