## DEFECT

**§2.3 / §2.2 / L1 — anon cannot join the activity channel.**  
`publishActivity` opens a second **private** channel `cswarm-activity:{workspaceId}`. `RealtimeChannel.send` only uses the socket when `canPush()` is true, and `canPush()` is `socket connected && channel joined` (`node_modules/@supabase/realtime-js/dist/module/phoenix/channelAdapter.js:63-65`). Join of a private channel uses **SELECT** RLS. The only SELECT policy on that topic is `TO authenticated` (`supabase/migrations/20260902000003_realtime_agent_activity.sql:4-16`). Anon already has SELECT only for `cswarm-wake:{wake_id}` (`20260906000010_wake_delivery.sql:242-249`). L1 adds INSERT only. Measured: a client without SELECT gets `CHANNEL_ERROR` (`tests/p1-local/activity-realtime-auth.test.ts:215-218`). A SELECT policy `TO anon` on the workspace activity topic would let anyone with the public anon key and a workspace UUID receive every frame. The spec does not name this, and L1 does not add a join policy that does not leak. The “over that socket” path is not reachable as written.

**§2.6 — policy refusal does not surface.**  
The spec says a refused proof makes `send` resolve `error`, then the controller counts `activity_publish_refused` and falls back. The cited `send` (`RealtimeChannel.js:520-566`) resolves `'ok'` at once when `broadcast.ack` is false (`:566-567`). That is the library default. `WakeSubscriber.connect` sets only `{ config: { private: true } }` (`src/listener/wake.ts:438-440`). L2 is not told to set `ack: true` on the activity channel. A refused INSERT is silent. No fallback.

**§2.4 — old site does not drop unknown keys.**  
Claim: “an old site build that drops unknown keys and a new one behave the same.”  
`parseAgentActivityFrame` rejects the whole frame if any key is outside `FRAME_KEYS` (`site/src/lib/agent-activity.ts:19-29, 78`). An old build that sees `proof` returns `null`. The panel goes blank. L3 before L2 limits the blast, but the claim about the old parser is false.

**§2.2 vs L1 — “stale” vs replay.**  
§2.2 accepts a captured replay (site drops non-newer `sequence`). The same section and L1 say the test “refuses … a stale one.” Stale is not defined. The HMAC message is `principalId || ':' || sequence || ':' || streamId` — no `emittedAt`, no nonce. The policy cannot refuse a replay without a new store the design rejected.

## GAP

**L2 wiring is unowned.**  
`ListenerActivityController` is built in `src/cli.ts:5916-5928` with only `AgentActivityEndpointTransport`. `WakeSubscriber` is created later in `src/listener/runtime.ts:1040-1046`. L2 names `cli.ts` as “status line” (`:4890-4891`, `:4970-4975`) and does not own `runtime.ts`. `publishActivity` has no path from the controller to the subscriber unless the author invents it.

**Socket frame shape vs HTTP body.**  
HTTP body is snake_case and has no `principalId` / `emittedAt` (`activity.ts:47-57, 119-128`). The site frame is camelCase `FRAME_KEYS` and requires `principalId` and `emittedAt` (`agent-activity.ts:19-29, 84-106`). The edge stamps both (`activity/index.ts:125-137`). Spec says the listener adds `proof` and stamps `emittedAt`. It never says to add `principalId`, where it is read (`cli.ts` has `options.principalId`; the controller does not), or that the socket payload is the site frame, not the HTTP body.

**HMAC bytes are not a shared constant.**  
L1 SQL and L2 Node must match on: UUID case, `sequence` as decimal text, UTF-8, and base64url with `=` stripped. Postgres `encode(..., 'base64')` is not base64url. The repo already uses `translate(encode(...), '+/=', '-_')` (`20260906000010_wake_delivery.sql:23-27`). The spec does not point at it.

**`realtime.messages.payload` shape for client INSERT is not specified.**  
The function reads `payload->>'principalId'`. Client `send({ type:'broadcast', event, payload })` may wrap that object. L1’s template inserts via SQL `realtime.send` and reads `message.payload` on subscribe (`activity-realtime-auth.test.ts:221-226, 264-267`). A SQL INSERT control can pass while L2 `channel.send` is refused.

**L2 `activityTransport` on the closed wake list.**  
`parseListenerWake` requires every `LISTENER_WAKE_STATUS_KEYS` entry (`wake.ts:59-67`, `control.ts:407-409`). `wake === null` makes the whole status malformed (`control.ts:596`). Adding `activityTransport` as required breaks current `status.json` wake blocks. Spec does not say the new key is optional.

**L4 evidence dir is unnamed.** Push-delivery named `docs/evidence/2026-09-06-push-delivery-measured/`. This spec says “evidence dir.”

**L1 “stale one”** (see defect): a lane would have to invent the meaning.
