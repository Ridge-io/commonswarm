#### 2. Static `file://` Harness vs. Live Dev Server
- **Load-bearing choice:** Load static HTML fixture pages via `file://` URLs in headless Chrome with query parameters rather than running an Astro preview/dev server.
- **Inversion:** Spin up a local Vite/Astro dev server to serve dynamic dashboard components during test runs.
- **Predicted failure:** Live server harnesses introduce port collisions, process teardown leaks, and network startup latency into CI test suites.

#### 3. Decoupled Dual-Launch (DOM Assertions vs. CLI Screenshots) vs. Single-Pass CDP
- **Load-bearing choice:** Separate DOM bounding-box measurement from image generation via distinct Chrome processes (`findChrome` DOM dump vs. headless CLI `--screenshot`).
- **Inversion:** Use a single interactive browser automation tool (CDP / Playwright) to measure layout and capture viewport buffers in one session.
- **Predicted failure:** Introducing heavy browser automation drivers adds dependencies outside the existing zero-dependency `findChrome` architecture and risks protocol disconnects in headless CI runs.
- **Beat the spec?:** No. Decoupling ensures that visual artifact generation does not block or flake the core DOM assertion suite.

#### 4. Explicit Pixel Targets (±2 px) vs. Visual Regression Image Diffing
- **Load-bearing choice:** Measure computed box heights/gaps in pixels with a ±2 px tolerance rather than bitmap diffing against golden screenshots.
- **Inversion:** Adopt perceptual pixel diffing (e.g., pixelmatch against Notion or Figma reference screenshots).
- **Predicted failure:** Cross-platform font rasterization, subpixel anti-aliasing differences (macOS vs. Linux CI), and line-height rounding trigger constant false-positive test breakages.
- **Beat the spec?:** No. Explicit mathematical assertions with ±2 px tolerance enforce rhythm reliably across environments.
