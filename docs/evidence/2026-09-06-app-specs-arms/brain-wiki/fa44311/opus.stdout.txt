**Seven defects**

1. **§1 "no topic-count cap" is false.** `FILE_WORKSPACE_MAX_NAMES = 500` (`file-artifacts.ts:54`, enforced `:517`), shared with every file artifact, and tombstoned names keep counting for 30 days. The spec cites `:52-53` — one line short. This kills §2.3's "at 500 topics" scaling, and prices §2.1's rename-by-copy at 86 of 500 names.
2. **§2.3's extraction cannot be "the same rule".** The message rule is the pure gate *plus* a DOM walk that skips `PRE/A/BUTTON` and feeds `codeSpan` from `CODE` (`brain-links.ts:92,:378-384`). A cached body has none of those. Measured above; contradicts `AGENTS.md:285-286` and a shipped test.
3. **The background fill has no size guard.** One member's legal 25 MB topic is pulled into every viewer's tab unasked; worst case is the 1 GB quota, which the source map stated and the spec dropped. `size_bytes` is already in the list (`read/index.ts:658`) — the guard was free.
4. **Each body is a command, not a read.** `file_download_url` writes one `swarm.idempotency_keys` row *and* one `swarm.audit_log` row (`command/index.ts:8368-8402`). The fill is 2N durable rows per viewer per session — more writes than the "shared write hotspot" §2.5 rejects.
5. **§2.4's anchors are not buildable.** The sanitizer allows attributes on three tags only; no `id` anywhere (`message-markdown.ts:73-78`), and its own comment calls a second attribute path the thing it exists to avoid. Author-controlled ids clobber `dashboard-brain-*`.
6. **The CLI cache has no principal and no revocation check.** Keyed by workspace only; `brain links` served from cache never asks the server, so a removed member keeps reading bodies (revocation is tested in `npm test`). Today no body ever touches disk.
7. **"First slice of roadmap H2" is false.** H2's three slices are `brain_search`, transcript banking, retention quota — and §2.5 defers the first one.
