### Findings

**GAP 1 — §4, cross-spec: `supabase/functions/command/index.ts` and the database slot have no order.**
L0 edits `supabase/functions/command/index.ts` and its after-column says "holds the local database". `docs/design/2026-09-06-MODEL-PER-AGENT.md:62` gives `lane/assigned-model` the same file ("`supabase/functions/command/index.ts` handlers") and the same slot. `assigned_model` appears in no migration in this checkout, so that lane is unlanded and the conflict is live. BRAIN-WIKI §4's "Shared files across specs" sentence names only `LiveDashboard.astro` and `message-markdown.ts`; MODEL-PER-AGENT §4 orders itself only against `read/index.ts` and HEARTBEAT. Both sibling specs order their shared **edge** file explicitly ("this spec's L1 lands first, then `lane/assigned-model` rebases"); this spec does not, for either the file or the exclusive database slot. An L0 author has nothing that says who rebases, and L0's own anchor `:8368-8402` moves if the other lane lands first. (`lane/claim-persistence` and `lane/wake-command` are *not* part of this: both are already in the code at `index.ts:8406-8459` and `durable-delivery.ts:21`.)

**GAP 2 — §2.3, the `sessionStorage` mirror is keyed by workspace only, with no user in the key and no eviction on sign-out.**
The spec writes `cswarm.brain.<workspaceId>.<topic>` and `cswarm.brain.<workspaceId>`. It gives bounds, an index key, and a `QuotaExceededError` rule, but never says what removes the mirror when the reader signs out or a second account signs in in the same tab. Measured: nothing in `site/src` clears `sessionStorage` on sign-out (only `localStorage.removeItem` calls at `LiveDashboard.astro:1902`, `:2777`, `:3087`, `:3153`), and the site's existing convention for browser-stored per-reader state **does** carry the principal — `createStorageKey = (userId) => \`commonswarm:app-create-intent:v1:${userId}\`` (`LiveDashboard.astro:1867-1868`). The spec applies this exact reasoning to reject the CLI cache in the §2.3 bullet ("needs a principal in the key, a TTL, and a revalidating read") and then adopts a browser mirror without it. L3 must invent the key's principal segment, the sign-out eviction, and whether to follow the `commonswarm:…:v1:` prefix convention or the new `cswarm.` one.

**NIT — §4 L3, "expose the DOM pass for a fragment" understates the change.** `linkifyBrainTopics` already takes `root: HTMLElement` (`brain-links.ts:329-334`), so a detached element works today; what it does not do is report *which* topics it found — it returns `created: number` (`:389`). L3 needs a returned topic set beside the existing count. Derivable from §2.3's `{topic → mentions[]}`, but the files column names the wrong change.

**NIT — §2.2 / §3, `cswarm brain tree` has no `--json`.** Every other brain verb carries `[--json]` (`cli.ts:562-564`) and `runBrainLs` branches on it (`cli.ts:7288`). The spec fully specifies the human line and is silent on JSON, so L1 invents whether it exists and its shape. No acceptance bullet depends on it.
