## 1. The Listener/Product Invariant: Model Starting Trace

Claim: *NOTHING in this change can start a model. The operator's absolute rule is that a headless agent must never answer on behalf of a main agent; the Claude preview channel must only wake the existing session.*

Attempted refutation trace across `src/cloud/agent-channel.ts`, `src/cloud/agent-host.ts`, and hook wiring:

1. `src/cloud/agent-channel.ts`:
   - Line 1: Explicit module invariant: `/** Claude channel transport. The host owns this stdio process; it never starts a model. */`.
   - Imports: No `node:child_process` (no `exec`, `spawn`, `fork`). No LLM provider SDKs (OpenAI, Anthropic, Gemini, Grok, ACP).
   - Lines 130-140: Uses `@modelcontextprotocol/sdk/server/index.js` `Server` exposing experimental `"claude/channel"` capability and a single tool `cswarm_received` (`CHANNEL_RECEIPT_TOOL`).
   - Line 185: Connects to `StdioServerTransport`. The parent host (Claude Code) initiates and owns this stdio connection.
   - Lines 233-240: Inbound signals from `claimAgentInbox` are emitted exclusively as notifications to the host session over MCP: `server.notification({ method: "notifications/claude/channel", params: { content: pending.row.signal.body, meta: { ... } } })`.
   - Lines 141-164: The channel only accepts `cswarm_received` confirmations from the host session. It never synthesizes responses, initiates model inference, or delegates to an agent worker.
2. `src/cloud/agent-host.ts`:
   - Lines 9-16: `parentProcess` calls `exec("ps", ["-p", String(pid), "-o", "ppid=,comm="], { timeout: 250, maxBuffer: 4096 })`. This only reads process executable names (`claude`, `codex`, etc.) up to 6 hops (line 22). It spawns no models or provider processes.
3. Hook wiring (`src/cloud/agent-receive.ts` and `src/onboarding-cli.ts`):
   - Lines 166-189 (`installReceiveHooks`): Installs `.claude/settings.local.json` or `.codex/hooks.json` containing command: `cswarm check --profile <profile> --hook --host-session-id <host>`.
   - Lines 224-231 (`configureAgentReceive` wake mode): Writes an MCP config `claude-channel-<host>.json` pointing to `cswarm receive serve --profile <profile> --host-session-id <host>`, and outputs start instruction: `claude --resume '<host>' --mcp-config '<config>' --dangerously-load-development-channels server:cswarm`. This resumes the *existing* Claude interactive session; it launches no separate worker.
   - `src/onboarding-cli.ts:80-105` (`runTurnHook`): Invoked by the host hook on `UserPromptSubmit`, `SessionStart`, or `Stop`. It reads JSON event from stdin (`hookInput()`), records idle status or calls `checkAgentMessages`, and prints untrusted teammate messages to stdout for the existing session.
   - Tests in `tests/p1-cli/permissions-default.test.ts:63-71`: Confirms ACP bridges (`claude-agent-acp`, `codex-acp`) and `--permissions` have been retired from onboarding.

Refutation result: REFUTED. No path in this change can spawn a provider or start a model.

     ```ts
     const pending = this.pending;
     if (!pending || hostSessionId !== this.hostSessionId || signalId !== pending.row.signal.id || receipt !== pending.receipt) {
       throw new AgentSetupError("channel_receipt_mismatch", "This receipt does not belong to the pending message in this session.");
     ```

     Enforces:

## 5. Installer Checksum-First Verification

Claim: *The checksum-first path fails closed on a malformed checksum and replaces damaged or changed bytes. A wrong reuse would ship a stale binary.*

Verification in `install.sh`:

1. Checksum Fetch & Validation (`install.sh:84-92`):
   - Downloads `$BASE/cswarm.sha256` first. Fails with `die` if download fails.
   - Parses `EXPECTED="$(cut -d' ' -f1 < "$TMP/cswarm.sha256")"`.
   - `case "$EXPECTED" in *[!0-9a-f]*|'') die "the release checksum is malformed — nothing was installed." ;; esac`
   - `[ "${#EXPECTED}" = 64 ] || die "the release checksum is malformed — nothing was installed."`
   Fails closed immediately if checksum is not exactly 64 hexadecimal characters.
2. Byte Comparison & Replacement (`install.sh:104-122`):
   - Compares SHA-256 of existing `$INSTALL_DIR/cswarm` against `EXPECTED`.
   - If equal, copies local binary to `$TMP/cswarm` ("Using the installed build; its checksum matches this release.").
   - If unequal, damaged, or modified, downloads fresh binary from `$BASE/cswarm`.
   - Always computes `ACTUAL="$(cswarm_file_hash "$TMP/cswarm")"` and verifies `[ "$EXPECTED" = "$ACTUAL" ] || die ...`.
   - Atomic replacement via `mv -- "$TMP/cswarm" "$INSTALL_DIR/cswarm"`.
3. Pinned in Unit Test:
   - `tests/p1-cli/onboarding-installer.test.ts:10-53`:
     - Initial download succeeds.
     - Repeat run reuses local file (0 new downloads, 2 manifest checks).
     - Local file modified with extra bytes: installer detects mismatch, downloads fresh binary, repairs local installation.
     - Malformed checksum (`"bad"`): installer exits with code 1, refuses to install, keeps original binary intact.

Refutation result: REFUTED. Installer fails closed on malformed checksums and replaces altered binaries.
