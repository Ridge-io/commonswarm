### Check 3: The abbreviation guard
The current `sentenceEnd()` correctly pulls all abbreviations ending in a period from `AUTH_PROVIDERS`. The regex `(?<!\b(?:Inc|LLC)\.)(?<=[.!?])\s+` successfully skips the space after `Inc.` or `LLC.`. Widening this boundary does merge two claims separated by an abbreviation into one unit. However, the sweep requires a unit naming any provider to exactly match the set of rendered providers. Therefore, merging sentences would only ever produce a false positive (failing when it shouldn't) if the text naturally split providers across valid abbreviation-ended sentences. It does not hide an offender. The risk is paid for because the old boundary caused false negatives by prematurely cutting sentences and separating sign-in verbs from the provider names.

### Check 4: The source sweep's bound
The comment stripper correctly ignores HTML comments (`<!-- ... -->`) and inline single-line JS comments, but this only leads to safe false positives. However, the surface derivation `signInSurfaces()` **can completely miss a page that offers sign-in**. If a new `.astro` page implements its own OAuth call (e.g., `<button onclick="supabase.auth.signInWithOAuth({provider: 'github'})">`) but never imports `ProviderButtons` or `auth-providers`, it will not be scanned by the source sweep. A concrete sentence that could ship past both sweeps is an error message inside a script tag on such an unscanned page: `<script>alert("Use GitHub to sign in");</script>`. The source sweep skips the file entirely, and the HTML sweep strips script bodies before checking.
