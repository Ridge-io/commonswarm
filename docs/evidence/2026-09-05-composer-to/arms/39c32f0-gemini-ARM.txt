1. **Hidden recipient.**
The paths are defended. A failed send deliberately leaves `composerToApplied` intact. Thus, tags whose chips were manually removed don't silently reappear when the user resumes typing. Workspace switches cleanly clear the address and restore the new workspace's saved set. A roster change mid-draft invokes `restoreComposerDraft`, but it bails when `restoredComposerDraftKey` matches, preserving the user's unsaved edits without overwriting the input.

2. **The wire body.**
If `browserSignalCommand` is called with both `recipients` (length > 0) and a `placement` containing `threadRootId`, it will construct a body with both `to` and `thread_root_id`. The edge's `chatSignalShapeProblem` will explicitly refuse this with: "A thread reply is readable by everyone who can read its thread, so it cannot also be addressed to a recipient."

3. **The wake claim.**
True for both. The `browserSignalKind` generator strictly checks `notifiedRecipient(recipients)`, returning an agent only if they are at `NOTIFIED_POSITION` (0). On the server, `swarm.enqueue_signal_delivery` relies on the scalar `to_agent_principal_id`, which the edge only populates from index 0. Agents beyond the front are never woken.

4. **The mention merge.**
The merge is robust against silent additions. `composerToApplied` reliably remembers tags whose chips were removed. Because it is not cleared on a failed send, typing again won't resurrect a deliberately deleted chip. If the tag is deleted from the text and then retyped, it naturally falls out of `applied` and successfully triggers the chip again.

Double-posting after a render fault is a case FIXED (new in this diff). In main, if a post reached the server but the client's subsequent render threw an error, draft cleanup was skipped. Reloading would then restore the draft with a null intent, mint a new `commandId`, and double-post. This diff introduces `if (landed) clearComposerDraft()` in the catch block to explicitly prevent this.
