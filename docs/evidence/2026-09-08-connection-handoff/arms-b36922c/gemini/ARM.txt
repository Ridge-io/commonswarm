## 2. Refutation Analysis of Specific Claims

### Claim 1: The fence is always longer than any backtick run inside the payload
**Source examined:** `site/src/components/connect/agent-prompt.ts` (`codeBlock` at line 54):
```ts
function codeBlock(language: string, text: string): string {
  const fence = "`".repeat(Math.max(3, ...Array.from(text.matchAll(/`+/g), match => match[0].length + 1)));
  return `${fence}${language}\n${text}\n${fence}`;
}
```
**Reasoning & edge cases:**
- **Text with no backticks:** `matchAll(/`+/g)` produces 0 matches. `Array.from` yields `[]`. `Math.max(3, ...[])` evaluates to `3`. The fence is `` ` `` x 3 (` ``` `), length 3 > 0.
- **Text with exactly 3 backticks (` ``` `):** Match length is 3. `match[0].length + 1` is 4. `Math.max(3, 4)` is 4. Fence length is 4 (` ```` `), which strictly exceeds 3.
- **Text with longer run of $k$ backticks:** Match length is $k$. `match[0].length + 1` is $k + 1$. `Math.max(3, ..., k + 1) >= k + 1 > k`. Fence length is strictly greater than any backtick run in `text`.
- **Run at start or end:** `/`+/g` has no anchors (`^` or `$`) and matches contiguous backtick sequences at any character offset, including index 0 and index `text.length - k`.
- **Enclosure:** Under CommonMark 0.31.2 (Section 4.5), an opening code fence of length $L \ge 3$ backticks can only be closed by a line containing at least $L$ backticks. Because `fence` has length $\ge \max(3, k+1)$ where $k$ is the maximum run length in `text`, every run of backticks in `text` has length $\le L - 1 < L$. Furthermore, `${text}\n${fence}` places a mandatory newline before the closing fence. Thus, backticks at the end of `text` reside on the preceding line and cannot merge into or form a closing fence.
- **Worst-case construction:** No input string can produce a fence of length $\le$ any backtick run in `text`. The claim stands.

### Claim 2: setup rejects Markdown-damaged input BEFORE authenticating
**Sources examined:** `src/cloud/agent-profile.ts` (`parseAgentConnection` lines 72-102) and `src/cloud/agent-setup.ts` (`setupAgent` lines 25-55):
- In `setupAgent`:
  ```ts
  const raw = await readSecureJsonFileIfPresent(connectionPath, ONBOARDING_MAX_FILE_BYTES);
  ...
  const connection = parseAgentConnection(raw);
  ...
  const identity = await withAgentDeadline(..., async (fetcher, signal) => {
    // network calls and credential use start here
  });
  ```
  `parseAgentConnection(raw)` executes completely synchronously before `withAgentDeadline` or any credential / network operations (`AgentCredentialSession.open`, `readAgentSignalDirectory`, `readAgentSignalPage`).
- **Detection checks in `parseAgentConnection`:**
  1. `raw.includes("\\_") || /^\s*```/.test(raw)`:
     - Runs strictly inside the `catch` block after `JSON.parse(raw)` has failed.
     - Valid JSON cannot contain an unescaped `\_` escape (RFC 8259 §7 only permits `\"`, `\\`, `\/`, `\b`, `\f`, `\n`, `\r`, `\t`, `\uXXXX`). An unescaped `\_` causes `JSON.parse` to throw `SyntaxError`.
     - If a JSON string legitimately had a literal backslash followed by an underscore, valid JSON serialization escapes it as `\\_`. `JSON.parse` parses `\\_` successfully without throwing, so the catch block is never reached.
     - Base64url JWTs use `[A-Za-z0-9_-]` and contain no backslashes.
     - Valid JSON envelopes start with `{` (or whitespace then `{`), never with backticks ` ``` `.
  2. `/^\s*\[[\s\S]*\]\(/.test(value.url)`:
     - Checks if `value.url` starts with Markdown link markup `[...](...`.
     - Under RFC 3986, valid URLs start with an alphanumeric scheme followed by `:` (e.g. `https://` or `http://`). IPv6 host brackets appear after the scheme (`http://[::1]/`), never at index 0.
     - No valid URL starts with `[`.
- Therefore, the rejection occurs prior to any credential session or network call, and none of the detection shapes can false-positive on a valid envelope, base64url token, or URL.
