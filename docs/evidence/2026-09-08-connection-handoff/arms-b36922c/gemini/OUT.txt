### 2. Analysis of Claims

#### Claim 1: The fence is always longer than any backtick run inside the payload
- **Analysis:** In [`site/src/components/connect/agent-prompt.ts`](file:///Users/yulanbot/Developer/Ridge.io/cloud-swarm/site/src/components/connect/agent-prompt.ts#L54-L57):
  ```ts
  function codeBlock(language: string, text: string): string {
    const fence = "`".repeat(Math.max(3, ...Array.from(text.matchAll(/`+/g), match => match[0].length + 1)));
    return `${fence}${language}\n${text}\n${fence}`;
  }
  ```
  - **No backticks:** `matchAll(/`+/g)` returns empty; `Math.max(3, ...[])` evaluates to 3 (` ``` `). Length 3 > 0.
  - **Exactly 3 backticks:** Match length is 3; `match[0].length + 1` is 4. `Math.max(3, 4)` is 4 (` ```` `). Length 4 > 3.
  - **Longer run of $k$ backticks:** Match length is $k$; mapped to $k + 1$. `Math.max(3, ..., k + 1) >= k + 1 > k`.
  - **Run at start or end:** `/`+/g` matches unanchored at any index.
  - **Enclosure:** Under CommonMark 0.31.2 (§4.5), a closing code fence requires a line with at least as many backticks as the opening fence $L$. Every backtick run inside `text` has length $\le L - 1 < L$, and `${text}\n${fence}` places a newline before the closing fence. Thus, no line in `text` can close the block early.
- **Worst-case test:** No finite string can produce a fence $\le$ an internal backtick run. The claim holds.

#### Claim 2: `setup` rejects Markdown-damaged input BEFORE authenticating
- **Analysis:** In [`src/cloud/agent-setup.ts`](file:///Users/yulanbot/Developer/Ridge.io/cloud-swarm/src/cloud/agent-setup.ts#L25-L40), `parseAgentConnection(raw)` is called synchronously at line 28, well before `withAgentDeadline` (lines 36–55), which initiates network calls (`AgentCredentialSession.open`, `readAgentSignalDirectory`, `readAgentSignalPage`).
- **Detection False Positives:**
  1. `raw.includes("\\_") || /^\s*```/.test(raw)` in [`src/cloud/agent-profile.ts`](file:///Users/yulanbot/Developer/Ridge.io/cloud-swarm/src/cloud/agent-profile.ts#L74-L78) runs only in the `catch` block after `JSON.parse(raw)` throws `SyntaxError`. In valid JSON, `\_` is an illegal escape (RFC 8259 §7); an intentional backslash-underscore in string content must be serialized as `\\_`, which `JSON.parse` parses successfully without entering `catch`. Base64url JWTs use `[A-Za-z0-9_-]` and never contain backslashes. Valid JSON envelopes start with `{`, never with backticks ` ``` `.
  2. `/^\s*\[[\s\S]*\]\(/.test(value.url)` checks for Markdown link syntax `[...](...`. Valid URLs (RFC 3986) start with an alphanumeric scheme followed by `:`, never `[` (even IPv6 literal brackets follow `http://` or `https://`).
- **Verdict:** Rejection is guaranteed prior to authentication or network access without false-positives on legitimate envelopes.
