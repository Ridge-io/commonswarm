## 1. Abandoning a live lease

I tried to break recovery. I did not.

Release runs only in the ask `while (terminal === null)` loop, **before** `engine.process`. It calls `journal.clearActive`. That write sets `active: null` from any phase. It does not run in `claim_pending` or `ack_pending`. It does not call `prepareAck` or `sendPreparedAck`.

After `clearActive`, `terminal` stays null, so the outer loop `continue`s. The next pass calls `reserveClaim` with a **new** `claimCommandId`. Replay of the old command id is dropped on purpose. Server step 6 still needs `lease_id IS NULL`, so the released row cannot be claimed again until step 2 clears a stale lease. `attempt_count` goes up only on a new claim, not on expiry. That matches “no extra attempt”.

`exactRecoveredLease` still runs only when journal phase is `leased`. A crash **before** release still replays the stored lease. A crash **after** release has nothing to replay; the row waits for `leased_until`.

Double-ack: no. `prepareAck` is behind `terminal !== null`. Release leaves `terminal` null.

Double-reply: the release path does not post. If the effect is already `done`, the **leased** recovery path acks it **before** the hold loop.

Lost: no. The row stays unacked. If `until` has already elapsed, the next claim expire-acks it in step 3. That is the server schedule, not a lost row.

`observed` is not sent at claim time. Notes never enter this hold loop.

## 2. Request amplification

After release, `if (terminal === null) continue` returns to the outer `while (true)`: one more read page, then `claimAgentInbox`. If the only pending row is still leased, `claimed === null`, phase is `claim_pending`, then `clearActive` and `sleep(pollMs)` (`LISTENER_IDLE_POLL_MS` = 2s).

That is one extra claim, then normal idle polling. It is more traffic than the old sleep-to-lease-expiry. It is **not** worse than idle. There is no tight loop with no sleep. Empty claims sleep. Claim rate at 2s is 30/min; server limit is 120/min.

A new unleased row gets a fresh 15m lease, so it cannot bounce `leaseSpent` at attempt 0 in a no-sleep chain.
