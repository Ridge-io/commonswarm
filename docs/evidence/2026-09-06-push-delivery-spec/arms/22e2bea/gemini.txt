### 2. Inversion Arguments Evaluation

#### Inversion (a): That owning the trigger functions as `postgres` is unsafe or unavailable on hosted Supabase.
- **Inversion Claim:** Assigning trigger functions to `postgres` represents an unacceptable privilege escalation vulnerability or will be rejected/unavailable in managed Supabase environments.
- **Spec & Evidence Analysis:**
  1. *Availability:* All migrations run through the Supabase CLI (`supabase db push`) or dashboard connect as the administrative superuser role `postgres`. `ALTER FUNCTION ... OWNER TO postgres` is standard across Supabase extensions and migrations. Furthermore, `realtime.send` is deployed into schema `realtime`, where `postgres` natively holds `USAGE` and `INSERT` privileges on `realtime.messages`.
  2. *Necessity:* Opus D1 established on the local stack that `swarm_admin` lacks `USAGE` on `realtime` and `INSERT` on `realtime.messages` (`has_schema_privilege('swarm_admin','realtime','USAGE') = false`). Granting table-level permissions to `swarm_admin` fails because `realtime.messages` is partitioned daily by the Realtime service, and newly created partitions do not reliably inherit grants.
  3. *Safety & Containment:* The trigger functions (`swarm.wake_agent_delivery()`, `swarm.wake_workspace_signal()`) are hardened with `SET search_path = pg_catalog`, preventing search-path hijacking. All table accesses (`swarm.agent_principals`) and function calls (`realtime.send`) are fully schema-qualified. The trigger takes no user parameters, executes no dynamic SQL, and only emits a content-free broadcast (`signal_id`, `enqueued_at`).
  4. *Codebase Precedent:* The existing activity edge function already relies on `RESET ROLE` to revert to the connection role `postgres` precisely to invoke `realtime.send` (`activity/index.ts:139-145`).
- **Verdict:** **BEATEN BY SPEC (Refuted).**

---

#### Inversion (b): That re-creating `agent_delivery_read_context` with an extra output column breaks a 0.1.56 client or the read edge during the apply window.
- **Inversion Claim:** Replacing `swarm.agent_delivery_read_context` via `DROP FUNCTION` / `CREATE FUNCTION` to add the 11th `OUT` column (`wake_id`) breaks backward compatibility for 0.1.56 listeners and causes runtime failures in `read/index.ts` during migration deployment.
- **Spec & Evidence Analysis:**
  1. *0.1.56 Client Isolation:* 0.1.56 listeners invoke the HTTP endpoint `POST /functions/v1/read`, never database functions directly. The response parser in `src/cloud/signals.ts:1211-1218` strictly parses known fields and silently drops unrecognized keys. The addition of `wake: { topic, event }` in the response is purely additive.
  2. *Apply Window Invariant:* In Postgres, function replacement inside a DDL transaction is atomic. The input argument signature `(bytea, uuid)` remains identical. Adding an OUT parameter changes the composite record return type; calling queries in the pre-L3 `read/index.ts:437-451` that select explicit columns continue resolving their requested fields without error.
  3. *Apply Sequence:* The lane sequencing in §6 explicitly enforces: L2 migration applied first → L3 read/command edge deployed second → L4 client deployed last. Pre-L3 `read` ignores the 11th column until L3 deploys; 0.1.56 clients ignore `wake` indefinitely and continue polling at their existing cadence.
- **Verdict:** **BEATEN BY SPEC (Refuted).**

---

#### Inversion (c): That the lane order still lets two lanes hold the local database at once.
- **Inversion Claim:** The revised lane schedule in §6 still allows concurrent database test execution or lock contention across lanes sharing the local database container.
- **Spec & Evidence Analysis:**
  1. *Resource Serialization Rule:* The local database is explicitly treated as an exclusive lock resource: any lane executing `test:p1-local` or `test:p1-server` requires exclusive access to prevent `db:reset` collisions (`tests/p1-cli/test-gate-coverage.test.ts:19-21`).
  2. *Verification of Database-Holding Lanes:*
     - L0 (idle cost constants): touches no database.
     - L1 (claim persistence): runs `test:p1-server`. Holds local DB exclusively.
     - L2c (credential redaction): pure unit tests, touches no database. Runs in parallel with L0/L1.
     - L2 (wake migration): runs `test:p1-local`. Scheduled strictly *after* L1 merges.
     - L2b (retention policy): runs `test:p1-local`. Scheduled strictly *after* L2 merges.
     - L3 (wake response & rotation): runs `test:p1-server`. Scheduled strictly *after* L2 merges.
     - L4 (listener client): fake-socket tests in CI; live local validation is an isolated manual step. Scheduled strictly *after* L0, L2b, L2c, and L3.
     - L5, L6, L7, L8: sequenced downstream; L6 runs site tests only with zero database interaction.
  3. All lanes touching the database (`L1 -> L2 -> L2b -> L3`) form a strictly serialized chain.
- **Verdict:** **BEATEN BY SPEC (Refuted).**

---

#### Inversion (d): That 'revocation by intent' leaves a credential path whose stale subscriber learns more than 'principal X has work'.
- **Inversion Claim:** Because rotation does not trigger on database-level cascades (such as grant expiry, run completion, or workspace archival), a stale subscriber holding an unrotated `wake_id` can observe sensitive message contents or metadata.
- **Spec & Evidence Analysis:**
  1. *Payload Boundary:* W1 and W4 define the wake payload strictly as:
     `{ "v": 1, "signal_id": "<uuid>", "enqueued_at": "<timestamptz>" }`
     The payload carries zero signal bodies, no sender principal, no channel names, no kinds, and no arguments.
  2. *Claim & Read Enforcement:* A wake conveys no capability to read data. To claim or read the payload, an agent must present a valid, unrevoked bearer token (`swm_agt_...`) to `POST /functions/v1/command` or `/read`. When credentials expire or are revoked via cascade, the claim/read calls are rejected with 401/403.
  3. *Channel Authorization:* Realtime RLS policy `agent receives its own wake` (W5) restricts anon listeners to matching `cswarm-wake:{wake_id}`. Stale subscribers cannot join workspace topics (`cswarm-signals:{workspace_id}`) or other principals' topics. The maximum possible leakage for a stale subscriber is knowing that a signal was enqueued for principal X at timestamp T—exactly "principal X has work".
- **Verdict:** **BEATEN BY SPEC (Refuted).**

---

#### Inversion (e): That the whole design is not worth it against lane A's 15-second poll (the strongest case for doing nothing).
- **Inversion Claim:** Lane A's simple constant change to a 15-second poll reduces invocations sufficiently that building push delivery adds unnecessary complexity.
- **Spec & Evidence Analysis:**
  1. *Latency Penalties:* Lane A introduces an unavoidable delivery latency of up to 15 seconds (mean 7.5 s) on every single delivery turn. In multi-agent collaborative workflows and interactive CLI commands, adding 7.5–15 seconds per hop degrades system performance and violates the operator requirement that the system "works well". Push delivery delivers wakes in < 0.5 s (sub-second observed locally).
  2. *Scaling Asymptotics:*
     - Lane A's 15 s polling cuts invocations by ~7×, but cost continues to scale linearly with seats: `seats × (1 / cadence)`. At 1,000 seats, Lane A consumes ~7.2 million edge invocations/day (~$140/mo); at 10,000 seats, it consumes ~72 million invocations/day (~2.16 billion/month, ~$4,300/mo).
     - Push delivery reduces idle edge invocations by 96% (from ~53,800 to ~2,200 per seat/day). At 1,000 seats, edge invocations drop to ~2.4M/day; with presence (Successor 1), 10,000 seats drop to ~4.6M/day (~$280/mo).
  3. *Persistence Write Amplification:* Under Lane A polling, each seat continues executing claims that hit `checkDeliveryRateLimit` minute buckets and consume database CPU. Push delivery eliminates per-tick polling, reducing rows written per idle day from 49,400 to ~400 short-lived rate-bucket rows.
  4. *Complementarity:* Lane A is not an alternative to push delivery; it is lane L0, which serves as the safety net and fallback transport during reconnects, outages, and proxy restrictions.
- **Verdict:** **BEATEN BY SPEC (Refuted).**
