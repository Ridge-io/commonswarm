2. FINDINGS
=====================================================================
DEFECT 1. §2.1 (and §0, both §2.4 rows, §9's bullet (a)) — the bound's exposure set is
stated as "exactly the set of signals with `--until` under LISTENER_RECONCILE_POLL_MS".
It is not. A thread reply with NO `--until` inherits its root's remaining horizon.

  command/index.ts:7029-7038 — the `until_value` CTE. When `untilExplicit` is false
  (i.e. the caller sent no `until_ms`), the value is
  `LEAST(now + default, COALESCE(untilCeiling, now + default))`, and `untilCeiling`
  is the thread root's `until` (:8046). The explicit branch does not clamp; it is
  refused instead (:8004-8023, and the WHERE at :7072-7073).

So a `cswarm ask --thread <root>` (or any directed reply) into a thread whose root has
40 seconds left is stored with `until = now + 40 s` although nobody typed `--until`
and the kind default is 7 days. That delivery sits in exactly the window the bound
describes: a dropped wake, a 300 s reconcile, step 3 terminalizes it as `expired`.

Two consequences, both in text the diff introduced:
  - §2.1's "the exposure is exactly the set of signals with `--until` under
    `LISTENER_RECONCILE_POLL_MS`" and §0's "a signal whose sender set an expiry
    shorter than the reconcile interval" are both false for this path; the sender set
    nothing.
  - §9's remedy (a), "the edge refuses or clamps `until_ms` below 2 ×
    LISTENER_RECONCILE_POLL_MS for directed signals", is written against `until_ms`
    only. Built as written it would leave the clamped-reply path open while the spec
    says the bound is closed. Remedy (b) (a second wake at `until − margin`) covers
    both, because it keys on the stored `until`.
Fix, one clause and one qualifier: say the exposure is every signal whose stored
`until` is under the reconcile interval — signals posted with `--until` below it, and
thread replies clamped to a nearly-expired root (`command/index.ts:7029-7038`) — and
scope §9(a) to the stored value rather than to `until_ms`. L7's measurement line
already says "signals under 5 minutes", which is the right instrument for both.
