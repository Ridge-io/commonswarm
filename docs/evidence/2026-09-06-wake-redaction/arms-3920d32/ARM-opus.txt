## R1 — REFUTE: `{43}` is the wrong bound for a wake_id

Spec: `docs/design/2026-09-06-PUSH-DELIVERY.md:68` — the column default is
`translate(encode(extensions.gen_random_bytes(32), 'base64'), '+/=', '-_')`, and
`:118` gives `rotate_wake_id` the identical expression. Both generators are the same
expression, so there is one length to check.

base64 of 32 bytes is 44 characters with exactly one `=` pad (32 = 10*3 + 2). `translate`
with a 3-char `from` and a 2-char `to` DELETES the third character, so `=` is removed and
`+`/`/` are substituted 1:1 — output is always exactly 43 characters from the alphabet
`[A-Za-z0-9_-]`. `encode(...,'base64')` wraps at 76 characters, and 44 < 76, so no newline
is injected. The length is therefore constant at 43 for both the migration default and
`rotate_wake_id`; it is not a uuid and never padded. `{43}` is right, and `{43,}` or `+`
would over-match against the spec.

Measured on the constant at `src/host/credential-redaction.ts:25-28`: a 43-char suffix
matches, a 42-char suffix does not, and a 44-char suffix is redacted for its first 43 with
one character left over (a residue of one base64url character, not a leak of the id).

REFUTATION FAILED. No defect.

## R4 — REFUTE: `lastIndex` lets a second secret through

`SECRET_SHAPE_RE` (`credential-redaction.ts:25-28`) carries `i` only — no `g`, no `y` — so
`.test()` never advances `lastIndex` (measured: 0 after a match). All three `.test()` callers
(`control.ts:437`, `:474`, `:830`) use that object. The `g` forms are separate objects
(`credential-redaction.ts:30`; `supervisor.ts:173` compiles a fresh one per call) and are used
only in `.replace`, which resets `lastIndex`. I could not construct a reachable pair of calls
that leaks. REFUTATION FAILED.

## R5 — REFUTE: the marker split leaks, or the widened class is a leak

`localDiagnostic` writes `[redacted]`; `parseStatus` rejects on `SECRET_SHAPE_RE`, not on a
marker, so a `localDiagnostic` output can never be rejected for carrying its own marker — and
the new control test asserts exactly that round-trip (the redacted detail persists and reads
back). Conversely a topic that survived `localDiagnostic` cannot exist, because the same
source drives both.

The class change in `localDiagnostic` (old `[^\s"'\\]*` → the separator class) makes the token
branch consume MORE characters (it no longer stops at `"`, `'`, `\`). That is a widening of
redaction, not a leak, and it makes `localDiagnostic` agree with `redactCredentialText`, which
already used the separator class. NIT only: a diagnostic containing `swm_agt_x"tail` now loses
`"tail` as well. Harmless for a bounded local string.
