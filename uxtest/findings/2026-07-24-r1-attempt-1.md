**The `path` bug is worth remembering as a class, not a typo.** `remote_zsh` runs `zsh -lic`;

command in the rest of the block vanished. Proven with a control (`zsh` vs `workspace_path` vs
`bash`) before the fix, and the mechanism is now in a code comment.

## 6. One error class, six faces in one evening

> **Absence of the artifact you happened to check is not absence of the thing.**
> An instrument that cannot produce a positive cannot produce a meaningful negative.

1. **An endpoint that answers is not an endpoint that delivers.** Lead4's SSH-origin bridge served
   a valid `Dana` agent-card for hours while being structurally incapable of pushing into the cmux
   tab (§1.2). It looked healthy from the mini the entire time.
2. **A registry entry is not the server.** `swarm members` lists `Anvil @ 127.0.0.1:18790`; the
   process actually serving that port self-identifies as `Yulan`. Reading the registry as evidence
   about the endpoint produced a wrong "the doc is stale" report — and the doc was corrected on the
   strength of it before being reverted (`71ec074`).
3. **A process with the right name is not the work.** `launch-human{1,2}.sh` treated "an agent
   called `Dana-r1` exists" as proof the virgin-context spawn had happened, skipping the probe, the
   distinct-surface assertion and the `carryover` flip. **Idempotence means the evidence is
   recorded, not that a process with that name exists.**
4. **A surface that exists is not a surface that accepts.** (Dana's phrasing, and the best of the
   set.) The retry path re-sends keystrokes to a surface whose input-readiness was never checked.
5. **A late artifact's absence is not non-execution.** The state *directory* appears at `:37`; the
   state *file* only at `:109`. Concluding "never ran" from the missing file required knowing which
   artifact appears first — and it doesn't tell you.
6. **★ An agent's report that something did not run is evidence about its tool layer, not about the
   filesystem.** Dana's entire tool result was *"the tool use was rejected… STOP what you are
   doing"* — for a child process that had already reached line 38. **An interrupt landing after
   `exec` is reported to the agent as though it landed before, and the agent cannot distinguish
   those two from inside.** So the false negative was unreliable **by construction, not by
   carelessness**, which matters: carelessness can be fixed by trying harder, and this cannot.
   For any "did X run?", go to the filesystem.

**The working detector that caught two of these tonight** is cheaper than the rule it implements:
**identical answers where the arms should have differed.** "Confirm the probe could have produced a
positive" requires imagining a counterfactual — exactly the imagination that fails when you are
tired and the result matches your hypothesis. "Did my two arms actually separate?" requires no
imagination; you just look. It caught an empty `sed` extraction that made all four test cases
"pass", and a `mkdir --version` check invalid on BSD that returned NOT_FOUND for *both* arms. In
both cases the broken instrument would have **confirmed** the hypothesis.

**What actually saved us tonight was not scepticism — it was artifacts with timestamps.** Testimony
was wrong in both directions (an agent's false negative about itself; two humans' inferences stated
as fact). The filesystem was right every time.

**Ruling (Lead5): do not use it, and do not revert it.**

Not using it, because using it is the strongest possible ratification and that is not ours to give.
Not reverting it, because **a revert is itself an unconsented write to the same file on the same
sleeping human's machine.** The error was not the *direction* of the edit; it was acting on someone's
config without consent. Undoing it without consent repeats the error and calls it a fix — and would
destroy the evidence, leaving the operator a file that looks untouched plus a story about it.

**What made this easy, and belongs in the reasoning:** the violation **does not even unblock us**.
It buys gate 5 and leaves us dead at gate 7 with the mini's identical gap. Trading a documented
ruling for a partial step that still produces no round is a bad trade at any price. *When a rule
looks expensive, check first whether breaking it actually buys the thing.* Often it doesn't, and
then there was never a dilemma.

### Revert instructions for the operator

**Do not restore the backup wholesale.** `~/.claude.json` is live and will have accumulated
unrelated changes overnight; a blanket copy would silently discard them. Remove the single key:

```bash

const v=JSON.parse(fs.readFileSync(p,"utf8"));
```

The backup at `~/.claude.json.bak-pretrust-1784950110` remains available as evidence of the
original state. If instead you wish to **keep** the flag, no action is needed — but please say so
